# Agent 調査・運用ガイドライン (System Instructions)

本リポジトリにおける調査エージェント（Agent）の基本行動指針、調査ワークフロー、およびルールを定めます。

---

## 🎯 目的と役割
本リポジトリは、特定のテーマ（例：「病理画像分野における画像認識AIの活用と最新研究」など）について深掘り調査を行い、信頼性の高い論文情報の集約、PDF等の資料管理、構造化された調査レポートの作成、および過去の調査を踏まえた次期テーマ提案を行うためのナレッジベースです。

---

## 🧭 基本運用ルール
1. **1フォルダ10アイテム以内の原則**:
   - フォルダが散らかるのを防ぐため、いかなるディレクトリでも同階層に並列して10個以上のアイテム（ディレクトリまたはファイル）が並ばないよう設計・運用する。
   - 調査テーマは必ず `topics/YYYY/MM/` 階層に作成し、フォルダ名には連番をつける（例: `topics/2026/08/01_pathology_ai_vision/`）。
2. **テンプレートの遵守**:
   - 新規調査時は必ず `templates/topic/` の構造をコピーして使用する。
3. **再現性とエビデンスの確保**:
   - 調査したクエリ、情報ソース（arXiv, PubMed, IEEE, ACM, Google Scholar, GitHub等）を記録する。
   - 重要な論文はリンクを正確に記載し、必要に応じて `papers/pdfs/` 配下に保存する。
4. **全体目次（INDEX.md）の常時同期**:
   - 調査を完了または新規作成した際は、必ずリポジトリ直下の `INDEX.md` にテーマ名、タグ、レポートリンク、サマリーを追記する。

---

## 🔄 Git 同期・コミット運用ルール
本リポジトリは複数セッション・複数Agentが継続的に読み書きする想定のため、作業の開始前後で必ず以下を行う。

1. **作業開始前**:
   - `git status` で未コミットの変更が残っていないか確認する。残っていれば内容を確認し、放置せず先にコミット（またはユーザーに確認）してから作業を始める。
   - `git pull` を実行し、リモート（`origin/main`）の最新状態を取得する。他セッションが追加した `topics/` や `INDEX.md` の更新を取り込まずに作業すると、後で競合・重複調査の原因になる。
2. **作業完了後**:
   - 新規/更新した `topics/...`, `INDEX.md`, `proposals/backlog.md` 等を `git add` し、内容が分かるコミットメッセージでコミットする（例: `research: 病理画像AIの基盤モデル動向を調査 (topics/2026/08/01_pathology_ai_vision)`）。
   - push は明示的にユーザーから指示があった場合のみ行う。指示がない場合はコミットまでに留め、pushするかどうかをユーザーに確認する。
3. **競合時**: `git pull` でコンフリクトが発生した場合、`topics/` 配下は基本的に追記型（新規ディレクトリ）なので自動マージされることが多いが、`INDEX.md` や `proposals/backlog.md` など複数人が同じ箇所を編集しうるファイルで衝突した場合は、変更を安易に上書きせず両者の内容を確認して手動でマージする。

## 🛠 調査ワークフロー

### Step 1: 調査テーマのセットアップ
1. 現在の年月を確認し、対応するディレクトリを作成（例: `topics/2026/08/`）。
2. その月の既存テーマ数を確認し、連番プレフィックスを付けてトピックフォルダを作成（例: `01_xxx`）。
3. `templates/topic/` 配下の構成（`report.md`, `papers/index.md`, `notes/` 等）をコピーして初期化する。

### Step 2: 文献・情報探索
1. 検索エンジン、arXiv API、PubMed、Semantic Scholar、学会プロシーディングス（CVPR, ICCV, MICCAI, NeurIPS等）等を活用して幅広く検索。
2. 検索キーワード、ヒット件数、選定基準を `notes/search_log.md` に記録。
3. 代表的なサーベイ論文、基礎論文、最新のSOTA/注目論文を5〜10本程度厳選。

### Step 3: 論文情報の整理とダウンロード
1. 厳選した論文の書誌情報、リンク、要約を `papers/index.md` に記載。
2. 重要な論文やオープンアクセスのPDFを取得可能な場合は `papers/pdfs/` にダウンロード（命名規則: `YYYY_FirstAuthor_ShortTitle.pdf`）。

### Step 4: 調査レポート（report.md）の作成
1. 背景と課題、主要アプローチの分類、SOTA手法の技術的詳細、比較分析、今後の展望・オープンクエスチョンを体系的に執筆。
2. 図表（Mermaidダイアグラム、比較表、アーキテクチャ概要等）を積極的に取り入れ、視覚的にもわかりやすくまとめる。

### Step 5: INDEX.md の更新 & 次のテーマ提案（任意）
1. `INDEX.md` に新規レポートの行を追加。
2. 今回の調査で明らかになった未解決課題や派生テーマがある場合、`proposals/backlog.md` に次期調査候補として提案を追記。
